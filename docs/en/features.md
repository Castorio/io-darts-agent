# IO-Darts-Agent - Features

## Overview

IO-Darts-Agent is a middleware solution that mediates between the Autodarts platform and various action modules. The hub receives real-time events from Autodarts and forwards them to configured modules.

## Core Features

### 1. Autodarts Integration

#### Authentication
- OAuth2-based login with Autodarts (Keycloak)
- Automatic token management and renewal
- Secure storage of credentials

#### WebSocket Connection
- Persistent WebSocket connection to Autodarts server
- Automatic reconnection on connection loss
- Heartbeat monitoring for connection stability

#### Event Processing

**Native Events** (from Autodarts):

| Event | Description | Data |
|-------|-------------|------|
| `match.start` | New match started | Match ID, board ID |
| `match.state` | Match state update | Players, scores, settings |
| `match.finished` | Match finished (winner determined) | Winner, final scores |
| `match.result` | Match result with full data | Chalkboard, stats, scores |
| `match.finish` | Match dismissed (user clicked "Finish") | Match ID |
| `match.delete` | Match cancelled | Match ID |
| `throw.detected` | Throw detected | Segment, points, multiplier |
| `game.finished` | Leg/Set won | Winner |
| `takeout.started` | Dart removal started | - |
| `takeout.finished` | Dart removal finished | - |

**Synthetic Events** (generated by EventParser):

| Event | Description | Trigger |
|-------|-------------|---------|
| `player.change` | Player changed | Player index changes in match.state |
| `turn.finished` | Turn finished | 3 darts thrown, bust, or round change |

### 2. Modular Plugin System

#### Module Architecture
- Each module is a standalone package
- Modules define their configuration via `module.json`
- Support for custom web UIs per module
- Modules can be installed from Git repositories
- Multi-language support (EN, DE, ES)

#### Module Lifecycle
```
Installation → Configuration → Start → Running → Stop → Uninstallation
```

#### Event Handling
- Modules register for specific events
- Parallel event processing for multiple modules
- Errors in one module don't affect others

### 3. Web Interface

#### Setup Wizard
- Guided initial setup
- Autodarts connection test
- Board selection

#### Dashboard
- Connection status
- Active modules
- Live event feed

#### Module Management
- View installed modules
- Start/stop modules
- Edit module configuration
- Install new modules (local or Git)

#### Player Management
- Create player profiles
- Individual colors per player
- Aliases for player name matching

#### Live Logs
- Real-time event log
- Filtering by event type
- Module-specific logs

#### Multi-Language
- English (en)
- German (de)
- Spanish (es)

### 4. Player Management

#### Player Profiles
- Name and aliases
- Individual color (for WLED, display, etc.)
- Automatic matching during Autodarts games

#### Color System
- RGB color selection
- Colors are passed to modules
- Fallback colors for unknown players

### 5. Configuration System

#### Hierarchical Configuration
```
Hub Config (hub.config.json)
├── Autodarts Credentials
├── Server Settings
└── Setup Status

Module Configs (config/modules/*.json)
├── wled.json
├── game-display.json
├── darts-caller.json
└── ...
```

#### Live Reload
- Configuration changes take effect immediately
- No server restart needed

## Built-in Modules

### WLED Lighting Controller

Controls WLED-compatible LED controllers based on game events.

**Features:**
- Various action types (Preset, Effect, Solid, Brightness, Off)
- Event-based configuration
- Player color integration
- Temporary effects with automatic restore to player color
- Multi-color effects (up to 3 colors)
- Fade time (transition time) for smooth color changes
- Single-player mode support
- Intent system support for module-to-module communication

**Supported Events:**
- Match start/end/result/finish
- Player change
- Throws (Triple, Double, Bullseye, Miss, 180)
- Bust
- Takeout finished

**Key Features:**
- **Duration with player color restore**: After a temporary effect, the player's color is restored (not the previous WLED state)
- **Fade Time**: Global and per-action transition time in milliseconds
- **Single-player support**: Player color is applied after match start and takeout in single-player games
- **Intent Actions**: React to intents from other modules (e.g., caller announcements trigger light effects)

### Game Display Module

Shows the current game score on a separate display in real-time.

**Features:**
- Large, readable score display
- Checkout suggestions (2-170 points)
- Animated player colors as background
- Throw display (Dart 1, 2, 3)
- Other players bar
- Responsive design for various screen sizes
- Demo mode for testing
- Configurable animations per event
- Idle mode options (waiting screen, last game, black screen, custom image)
- Multi-language support
- Configurable background colors

**Animations:**
- Support for multiple media types: Built-in, GIF, Video
- Optional sound playback with each animation
- Events: 180, Bull, Double Bull, High Score, Bust, Checkout, Leg Win, Set Win, Match Win

**Player-Specific Animations:**
- Individual animations per player in the "Players" configuration tab
- Players can have unique animations for: 180, Leg Win, Set Win, Match Win, Checkout
- Player animations override global animations when that player is on throw
- Supports: Built-in animations, GIF, Video, and custom sounds
- Perfect for personalized celebrations and unique player experiences

**Match Start Handling:**
- Automatically fetches full match data via API when match starts
- Prevents showing default values (501, "Player") at game start
- Match started screen with configurable display modes (default animation, custom image/GIF)

**Match Results:**
- Match results table with chalkboard and statistics
- Configurable display duration (auto-hide after timeout or manual dismiss)
- Configurable background color for results screen

### Darts Caller Module

Professional darts caller with TTS or custom audio packs.

**Features:**
- Score announcements after each turn
- Checkout calls ("You require...")
- Special calls: 180, bust, game shot, match shot
- Player change announcements
- Multiple output modes:
  - Browser TTS (Text-to-Speech)
  - Audio packs (pre-recorded MP3s)
  - Local playback (server-side audio)

**Voice Pack Generator:**
- Integrated ElevenLabs TTS support
- Generate complete voice packs with custom voices
- Configurable stability and clarity
- All required files generated automatically (scores, checkouts, special calls)

**Event Timing:**
- Uses synthetic events (`turn.finished`, `player.change`) for correct timing
- Score announced after turn, checkout announced after player change

## AI Features

IO-Darts-Agent includes a comprehensive AI integration system that enables powerful features across all modules.

### AI Provider System

The hub manages connections to multiple AI providers through a unified interface:

| Provider | Type | Capabilities | Status |
|----------|------|--------------|--------|
| **ElevenLabs** | TTS | Voice synthesis, voice packs | Production |
| **Runway ML** | Video | Animation generation (Gen-2/Gen-3) | Production |
| **OpenAI** | Multi | Text, images, embeddings | Available |
| **Anthropic** | LLM | Text generation | Available |
| **Stability AI** | Image | Image generation | Available |
| **Ollama** | Local LLM | Local text generation | Available |
| **Replicate** | Multi | Various models | Available |

### ElevenLabs Integration

**Voice Pack Generation:**
- Generate complete caller voice packs using any ElevenLabs voice
- All scores (0-180), checkouts, special calls automatically generated
- Voice preview and selection UI
- Character usage tracking and quota display

**Dynamic Player Name Synthesis:**
- Automatically detect new players at game start
- Generate player name audio in real-time via ElevenLabs TTS
- Cache generated names for future games
- Seamless integration with existing voice packs

**Configuration:**
- Voice selection from available ElevenLabs voices
- Stability and similarity boost settings
- Model selection (eleven_multilingual_v2, etc.)
- Audio format options (MP3, WAV, OGG, FLAC)

### Runway ML Animation Generation

**Text-to-Video:**
- Generate custom animations from text prompts
- Ideal for celebration animations (180, checkouts, wins)
- 5-10 second video clips
- Multiple aspect ratio support (16:9, 9:16, 1:1)

**Image-to-Video:**
- Animate static images (player photos, logos)
- Create personalized player entrance animations
- Motion effects from still images

**Use Cases:**
- 180 celebration videos
- Leg/Set/Match win animations
- Player-specific victory animations
- Custom checkout celebrations
- Tournament intro videos

**Job Management:**
- Asynchronous generation (videos take 30-90 seconds)
- Progress tracking and status updates
- Job cancellation support
- Automatic retry on failure

### AI Configuration

Configure providers in **Settings > AI Providers**:

1. **Add API Key**: Enter your provider API key
2. **Enable Provider**: Toggle to activate
3. **Test Connection**: Verify API key works
4. **Configure Options**: Set provider-specific settings

Provider configuration is stored in `config/ai-providers.json`:

```json
[
  {
    "id": "elevenlabs",
    "type": "elevenlabs",
    "name": "ElevenLabs",
    "apiKey": "your-api-key",
    "enabled": true,
    "options": {
      "defaultModel": "eleven_multilingual_v2"
    }
  },
  {
    "id": "runway",
    "type": "runway",
    "name": "Runway ML",
    "apiKey": "your-api-key",
    "enabled": true
  }
]
```

### Module AI Access

Modules can access AI providers through the hub's unified interface:

- **Darts Caller**: Uses ElevenLabs for voice packs and player names
- **Game Display**: Can use Runway for custom animations
- **Custom Modules**: Full access to all configured providers

See [Module SDK](module-sdk.md) for integration details.

## Technical Details

### Performance
- Minimal latency in event processing (<10ms)
- Efficient WebSocket communication
- Lazy-loading for module UIs
- AI requests are asynchronous and non-blocking

### Security
- Credentials are stored locally only
- No external data transfer except to Autodarts and configured AI providers
- API keys are stored securely in local config
- Local access to web interface recommended

### Compatibility
- Node.js 18+
- Modern browsers (Chrome, Firefox, Safari, Edge)
- WLED Version 0.13+

### API
- REST API for configuration and control
- WebSocket API for real-time events
- Module UI routing (`/module-ui/:moduleId/`)
- AI provider endpoints (`/api/ai/*`)

See [API Documentation](api.md) for details.
