# IO-Darts-Agent: Features

## Overview

IO-Darts-Agent is a local hub between the Autodarts platform and various action modules. It receives your board's real-time events and forwards them to the configured modules (lighting, display, voice announcements).

> IO-Darts-Agent is an unofficial project and not affiliated with Autodarts. The hub is built for use in a local network and must not be reachable from the internet. License: PolyForm Noncommercial 1.0.0, free for private, non-commercial use.

## Core Features

### 1. Autodarts Integration

#### Authentication
- Login with email and password at the official Autodarts API (auth service v1, `api.autodarts.com/auth/v1`)
- Automatic refresh of the access token before it expires; if a refresh is rejected, a new login with the stored password
- No support for two-factor authentication (2FA)
- Credentials are only stored locally on the hub machine (`dist/config/hub.config.json`, plain text)
- Entered in the setup wizard or later under **Settings > Autodarts**

#### WebSocket Connection
- Persistent WebSocket connection to the Autodarts server
- Short-lived ticket per connection, requested again on every reconnect
- Automatic reconnection after connection loss

#### Event Processing

**Native events** (from Autodarts):

| Event | Description | Data |
|-------|-------------|------|
| `match.start` | New match started | Match ID, board ID |
| `match.state` | Match state update | Players, scores, settings |
| `match.finish` | Match closed (user clicked "Finish") | Match ID |
| `match.delete` | Match cancelled | Match ID |
| `throw.detected` | Throw detected | Segment, points, multiplier |
| `takeout.started` | Dart takeout started | - |
| `takeout.finished` | Dart takeout finished | - |

**Synthetic events** (generated by the EventParser):

| Event | Description | Trigger |
|-------|-------------|---------|
| `player.change` | Player change | Player index changes in match.state |
| `turn.finished` | Turn finished | 3 darts thrown, bust or round change |
| `game.finished` | Leg won (winner, leg, set) | Winner detected in match.state |
| `match.finished` | Match ended (winner determined) | Match winner detected in match.state |
| `match.result` | Match result with complete data (chalkboard, statistics, scores) | Emitted right after `match.finished` |

> **Note on array rotation:** Autodarts rotates the player array after each leg. The synthetic events therefore contain both `playerName`/`winnerName` and `playerIndex`/`winnerPlayerIndex` for robust player detection. Details in the developer guide.

### 2. Modular Plugin System

#### Module Architecture
- Built-in modules: WLED, Game Display, Darts Caller
- Each module describes its events, configuration and translations in a `module.json`
- Modules can have their own web UI (e.g. the Game Display at `/module-ui/game-display/`)
- Further modules can be installed from Git repositories or a local path and run as separate Node processes

#### Module Lifecycle
```
Installation > Configuration > Start > Running > Stop > Uninstall
```

#### Event Handling and Intents
- Modules subscribe to specific events
- Errors in one module do not affect others
- Intent system for module-to-module communication, configurable under **Intent Reactions**

### 3. Web Interface

#### Setup Wizard
- Step 1: optional login for the web interface
- Step 2: Autodarts credentials and board ID with connection test
- Step 3: summary and finish

#### Dashboard
- Active modules, uptime, events today
- Autodarts connection status with disconnect and connect, active match
- Module list and live event feed

#### Module Management
- Installed and available built-in modules
- Start, stop, restart, autostart
- Module configuration, intent reactions, statistics
- Install new modules (Git or local), uninstall

#### Player Management
- Player profiles with name, color, avatar and optional Autodarts user ID

#### Media Library
- Animations, sounds and images with folders, search, upload (up to 50 MB) and copy URL

#### AI Providers
- API keys, default models and connection test for all AI providers

#### Console
- Real-time log with event, module and system entries
- Filters, search, pause, auto-scroll, export, clear

#### Settings
- Language, server (host, port), web authentication, Autodarts access, developer mode
- The server host is stored but currently ignored: the hub always binds to `0.0.0.0`

#### Developer Tools
- Simulate matches, throws and turns without a real board (after enabling developer mode)

#### Multi-Language
- Interface in 10 languages: German, English, Spanish, French, Italian, Japanese, Dutch, Russian, Ukrainian, Chinese
- German and English complete, the others partly translated

### 4. Player Management

#### Player Profiles
- Name, color (palette or hex code), avatar
- Matched to Autodarts players by name (case-insensitive)

#### Color System
- Profile colors are passed to WLED and the Game Display
- For players without a profile, WLED uses position colors (up to 6 players)

### 5. Configuration System

```
config/
├── hub.config.json         Autodarts access, board, server, web login
├── ai-providers.json       AI providers, API keys, models
├── animation-settings.json Selected engine of the animation generator
├── players.json            Player profiles
└── modules/*.json          Module settings
media/                      Media library (animation, sound, image)
data/voicepacks/            Darts Caller voice packs
data/tts-cache/             Cache for ElevenLabs calls
```

When running from source these folders live under `dist/`. Credentials and API keys are stored in plain text.

## Built-in Modules

### WLED Lighting Controller

Controls WLED-compatible LED controllers based on game events.

**Features:**
- Action types per event: Preset, Effect, Color, Off, None
- Presets and effects are loaded straight from the controller, with a built-in effect list as fallback
- Effects with up to 3 colors, speed, intensity and brightness
- "Use player color" option per action
- Duration per action, afterwards the current player color is restored
- Fade time per action
- Single-player support: player color after match start and after every takeout
- Player colors for up to 6 positions as fallback
- Test button per action and quick actions (Rainbow Test, LEDs off, Green, Red)
- Reacts to intents from other modules

**Supported events:**

| Group | Events |
|-------|--------|
| Match Events | Match started, Match finished, Match left, Match cancelled |
| Throw Events | Throw detected, Triple hit, Double hit, Single Bull, Bullseye!, 180!, High Finish, Miss |
| Player Events | Player changed, Turn started, Turn finished |
| Board Events | Pulling darts, Darts pulled |

**Note:** "High Finish" is listed as an event in `module.json`, but the WLED module currently never triggers it: there is no checkout detection in the throw mapping. An action configured for it has no effect until this is implemented.

### Game Display Module

Shows the current score fullscreen on a separate device. Display URL: `http://192.168.1.100:3000/module-ui/game-display/` (IP of the hub machine).

**Features:**
- Large score display with the player color as background
- Checkout suggestions (threshold adjustable, default 170)
- Throw display (dart 1, 2, 3) and turn sum
- Bar with other players
- Optional game info overlay (position, size, offset adjustable)
- Idle mode: Show Last Game Score, Black Screen, Custom Image
- Match start screen: default (Game On!) or custom image/GIF, duration and background color adjustable
- Results table after the match with chalkboard and statistics, display duration and background color adjustable
- Preview, "Open Display" and "Copy URL" in the configuration
- Full match data is fetched automatically at match start

**Animations per event:**
- 180, Bull, Double Bull, High Score (threshold adjustable), Checkout, Leg Win, Match Win, Bust
- Type: Disabled, Built-in, GIF or Video, each with an optional sound and its own duration
- Leg and match win also with winner name, statistics, effect (Confetti, Fireworks, Sparkles) and colors
- Media via upload, from the media library or as an external URL
- Animation generator right in the Animations tab

**Player-specific animations:**
- Custom animations per player in the **Players** tab for: 180, Leg Won, Match Won, Checkout
- Replace the global animation when this player triggers the event
- Without a player entry the global animation applies

### Darts Caller Module

Darts caller with browser TTS, voice packs, ElevenLabs or custom audio files.

**Features:**
- Score calls after each turn
- Checkout calls ("You require ...")
- Special calls: 180, bust, no score, game on, game shot, match shot
- Player change calls with player names
- Languages: English, German
- Caller types: Browser TTS (played in the browser), AI Voice Pack, ElevenLabs Live AI, Custom Audio Files (played on the speakers of the hub machine)
- Call settings: scores, high scores only, checkouts, player change, game start, game over, 180, busts, bulls, double bulls
- Volume and delay adjustable

**ElevenLabs:**
- Uses the ElevenLabs key from the AI provider settings
- Choice of the voices in your ElevenLabs account
- Voice pack generator: scores 0 to 180, all possible checkouts 2 to 170 and special calls, with progress and cancel
- Multiple voice packs (different voices and languages), upload as ZIP, select and delete
- Missing player names are generated automatically at match start (with a voice pack active)
- TTS cache for live calls, repeated phrases are not requested again

## AI Features

### AI Providers

Providers are set up under **AI Provider** in the sidebar. All of them are optional.

| Provider | Type | Use |
|----------|------|-----|
| **OpenAI** | Text, image, speech, embeddings | Available to modules |
| **Anthropic** | Text | Available to modules |
| **Ollama (Lokal)** | Local text models | Available to modules, no API key |
| **ElevenLabs** | Speech synthesis | Darts Caller |
| **Stability AI** | Image | Available to modules |
| **Runway ML** | Video | Animation generator |
| **Higgsfield** | Video, image | Animation generator |
| **Replicate** | Text, image, video | Available to modules |

**Functions:**
- API key, default model, save, test connection, on/off per provider
- Stored on the hub in `dist/config/ai-providers.json`
- OpenAI and Anthropic: the model list is loaded live from the provider with the saved key. Models that are no longer offered are reported and replaced.
- Higgsfield: key in the format `KEY_ID:KEY_SECRET`, fixed catalog with 20 text-to-video and 10 text-to-image models, separate selects for video and image model (defaults: Kling 3.0 Standard and Soul Standard)
- Higgsfield requests are adapted per model: allowed duration, supported aspect ratio, audio off

> Generations cost credits at the respective provider.

### Animation Generator

Creates animations for the Game Display with AI. Found in the Game Display configuration in the **Animations** tab.

- **Engine**: Runway or Higgsfield, switchable, the choice is stored in `dist/config/animation-settings.json`
- **Styles**: Fire, Ice, Neon, Gold, Cartoon, Minimal, Electric, Confetti, Smoke, Stars or a custom style with name and description
- **Events**: 180, Bull, Double Bull, High Score (160+), Checkout, Leg Win, Match Win, Bust
- **Batch generation**: one job per selected event
- **Jobs**: status, progress, cancel, preview, "Use" (sets the animation for the event), "Clear Finished"
- **Result**: converted with `ffmpeg` into a transparent WebM (black background removed). Without `ffmpeg` the original is kept as MP4.
- **Location**: media library, Animations, folder `ai-generated/<style>`

## Technical Details

### Security
- Built for a trusted local network; do not expose it to the internet, no port forwarding
- Credentials and API keys are stored in plain text on the hub machine
- Connections only to Autodarts, your devices in the network and configured AI providers
- Optional login for the web interface

### Compatibility
- Node.js 22 or newer (when running from source)
- Current browsers (Chrome, Firefox, Safari, Edge)
- WLED controllers with JSON API
- `ffmpeg` optional for transparent animations

### API
- REST and WebSocket API, see the [API documentation](api.md)
